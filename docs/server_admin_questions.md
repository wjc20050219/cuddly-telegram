# 服务器使用咨询清单（给管理员）

> 用途：RiceVar-ID 项目需要在学校服务器上做测序数据下载与比对计算。
> 本文档可直接转发给管理员；若管理员只有 2 分钟，见第二节的 5 个核心问题。
> 编制日期：2026-09-16

---

## 一、给管理员的背景说明（可直接转发）

> 老师您好，我在做一个水稻品种鉴定的科研项目，需要用到学校的计算服务器。
>
> **项目做什么**：从公开数据库下载已发表的水稻全基因组测序数据（这些数据本来就是公开免费的，
> 如 NCBI、EBI 等国际公共数据库），在服务器上做比对和变异检测，产出一份品种特征表。
> **不做实验**，只用公开数据。
>
> **需要的资源量**（分阶段，可先给小的）：

| 阶段 | 样本数 | 数据量 | 计算量 | 时长 |
| --- | ---: | --- | --- | --- |
| **先试跑**（第一步） | 5 份 | 约 47.7 Gb 碱基 / **23.19 GiB 压缩** | 约 10 核时 | 数小时 |
| 小规模 | 20–50 份 | 约 280 Gb / **170.70 GiB** | 约 60–250 核时 | 1–3 天 |
| 正式（若顺利） | 100–1000 份 | 0.5–5 TB | 300–5,300 核时 | 1–2 周 |

> 碱基数取自 `data/metadata/candidates/candidate_samples.tsv` 的 `base_count` 字段，
> 压缩体积取自各面板清单的 `fastq_bytes`（成对文件为 `;` 分隔，需分别求和）。
> 注意 `base_count` 是**文库声明值**，不是我们实测的碱基数。

> 如果方便，**建议先只批第一步（5 份样本）**，跑通后再申请更多。

## 二、如果只有 2 分钟：请只回答这 5 个问题

这 5 个问题的答案决定了整个技术方案怎么搭，其余问题都可以后补。

| # | 问题 | 为什么关键 |
| --- | --- | --- |
| **1** | 有没有**作业调度器**？是 Slurm、PBS、LSF 还是别的？还是直接 `nohup` 跑？ | 决定全部脚本的提交方式。有调度器和没有调度器，脚本写法完全不同 |
| **2** | **计算节点能访问外网吗**？能访问 `www.ebi.ac.uk` 和 `eutils.ncbi.nlm.nih.gov` 吗？ | 决定数据是在服务器下载，还是必须本机代下再上传。**这一条影响最大** |
| **3** | 我能用**多少存储空间**？有没有 scratch/临时高速盘，配额多少、多久清理？ | 决定能处理多少份样本。本机磁盘装不下，这是主要瓶颈 |

## 三、完整清单（按主题分组）

> 每项给出「问题 / 为什么问 / 答案影响什么」，便于管理员判断。

### A. 账号与登录

| 问题 | 为什么问 | 影响 |
| --- | --- | --- |
| 我是否已有账号？如何申请？大概多久？ | 一切前提 | 决定能否开工 |
| 如何登录？SSH 直连、跳板机、还是必须校内网？ | 决定我能否从办公室/家里连 | 若必须校内网，需调整工作方式 |
| 是否需要 VPN？VPN 如何申请？ | 同上 | 同上 |
| 有没有现成的用户手册/文档？ | 避免反复打扰 | 提高效率 |

### B. 作业调度器（最关键之一）

| 问题 | 为什么问 | 影响 |
| --- | --- | --- |
| 是否有调度器？**Slurm / PBS(Torque) / LSF / SGE / 无**？ | 决定脚本提交方式 | **全部流程脚本需按此改写**（`run_all.sh` 只实现了 Slurm 分支） |
| 如果有：有哪些**分区/队列**？各自适用什么任务？ | 我需知道把作业投到哪里 | 决定并行策略 |
| 单个作业最多可用**多少 CPU 核**？多少内存？最长运行多久？ | 决定单样本并行度与分块 | 影响总时长 |
| 是否需要排队？通常等多久？有没有优先级别？ | 决定预期进度 | 影响时间规划 |
| 有没有**提交脚本模板**可以给我参考？ | 直接复用最省事 | 减少出错 |
| 计费吗？有配额限制吗？ | 成本与额度 | 决定规模 |

> **为什么最重要**：本项目的核心计算（比对 + 变异检测）是典型的"单样本独立、可大规模并行"任务。
> 有调度器时可以一次提交几十上百个作业；没有调度器则要自己用 `nohup`/`tmux` 管进程。
> 两种情况的脚本与容错策略完全不同，**必须提前知道**。

### C. 外网访问（最关键之一）

| 问题 | 为什么问 | 影响 |
| --- | --- | --- |
| **计算节点**能否访问外网？还是只有**登录节点**能？ | 下载通常在登录节点做，计算在计算节点做 | 决定下载步骤放在哪 |
| 能否访问 `www.ebi.ac.uk`（欧洲生物信息研究所，数据主源）？ | 数据来源 | 不能访问则需本机代下 |
| 能否访问 `eutils.ncbi.nlm.nih.gov`（美国 NCBI）？ | 数据来源与交叉核验 | 同上 |
| 能否访问 `ftp.ncbi.nlm.nih.gov`？ | 备用下载源 | 同上 |
| 能否访问 `mirrors.tuna.tsinghua.edu.cn`（清华镜像）？ | 装软件要用 | 不能则装环境困难 |
| 有没有 **HTTP 代理**？地址和端口是？ | 若需代理才能出网 | 直接决定脚本能否联网 |
| 有没有**下载限速**或流量限制？ | 我们有 TB 级下载计划 | 决定下载策略与耗时 |
| 能否访问 `github.com` / `pypi.org` / `anaconda.org`？ | 装软件与拉取脚本 | 影响环境搭建 |

> **为什么最重要**：整个技术方案是"**在服务器下载 + 比对，只把结果表传回本机**"。
> 如果服务器不能出网，这个方案要改成"本机下载 + 上传"，工作量和时间都会显著增加。
> 实测本机到 EBI 是通的（可作为参照基线），所以只需确认服务器侧。

### D. 存储

| 问题 | 为什么问 | 影响 |
| --- | --- | --- |
| **家目录配额**多少 GB？ | 通常配额很小，装不下测序数据 | 决定数据放哪 |
| 有没有 **scratch / 临时盘 / 高速盘**？配额多少？ | 大数据计算通常放这里 | 决定能否处理大数据量 |
| scratch 的数据**多久会被清理**？ | 决定要不要及时导出结果 | 影响流程设计 |
| 有没有**项目共享目录**？多人协作怎么放？ | 若后续有人协作 | 影响目录结构 |
| 存储**备份**策略是什么？ | 决定我是否需要自己备份 | 影响数据安全 |
| 文件系统是**并行文件系统**（如 Lustre）吗？ | 影响大量小文件的性能 | 影响 I/O 策略 |

> **为什么重要**：本项目的实测瓶颈是**磁盘而非 CPU**。
> 一份 10× 样本需要约 2 GB 最终存储、工作期间约 5 GB。
> 1000 份样本需要 2 TB 净空间、4–5 TB 工作空间。**这是决定规模上限的因素。**

### E. 软件环境

| 问题 | 为什么问 | 影响 |
| --- | --- | --- |
| 是否预装 **conda / mamba / micromamba**？版本？ | 我需自建独立环境 | 决定环境搭建方式 |
| 允许**自建 conda 环境**吗？还是只能用系统环境？ | 我们需要特定版本的工具 | **若不允许，方案需大改** |
| 是否允许 **pip install**？ | 装 Python 依赖 | 同上 |
| 有**模块系统**（`module load`）吗？ | 有的集群用模块管理软件 | 影响调用方式 |
| 是否允许 **Singularity / Apptainer / Docker** 容器？ | 容器可免去装环境的麻烦 | 是更省事的替代方案 |
| 已预装哪些生信工具？（samtools / bcftools / bwa / bwa-mem2 / mosdepth 等） | 能复用就不重复装 | 省时间 |

> **为什么重要**：分析流程依赖一组特定工具与版本（samtools 1.24、bcftools 1.24、
> bwa-mem2 2.3、mosdepth 0.3.14 等）。若有容器支持，可直接用现成镜像，最省事。

### F. 资源规格

| 问题 | 为什么问 |
| --- | --- |
| 计算节点 **CPU 核数**与型号？ | 估算总时长 |
| 单节点**内存**多少 GB？ | 比对需约 2 GB/核，建索引需约 1 GB |
| 有几台节点？是否共享？ | 判断实际可用算力 |
| 有没有 **GPU**？（我们暂不需要，仅了解） | 备选加速方案 |

### G. 合规与数据管理

| 问题 | 为什么问 | 影响 |
| --- | --- | --- |
| 允许**下载并存储公开基因组数据**吗？ | 合规前提 | 若不允许，方案不成立 |
| 分析**结果能否拷回本机**？ | 我们的分工是"服务器算、本机分析写作" | 影响工作流 |
| 有没有**数据出境/知识产权**方面的要求？ | 数据来自国外公共库 | 影响论文数据声明 |
| 服务器使用是否有**须遵守的规范文件**？ | 避免违规 | 需提前了解 |

## 四、更省事的替代方案：直接跑探测脚本

如果管理员不方便逐条回答，**可以把 `server/` 目录上传到服务器，跑一个脚本**，
5 分钟内自动给出上述大部分答案（比人工回答更准确）：

```bash
# 在服务器上（无需管理员权限即可运行大部分检查）
bash 00_probe.sh
```

脚本会输出 `logs/probe_report.txt`（人读）与 `logs/probe_summary.tsv`（机读），内容覆盖：

| 脚本自动回答的 | 对应问题 |
| --- | --- |
| 系统、CPU 核数、内存、架构 | F |
| 各路径可用空间、用户配额 | D |
| 是否有 sbatch / qsub / bsub，队列情况 | B |
| 是否有 conda / mamba / module / singularity / docker | E |
| 已装哪些生信工具（18 个逐个检查） | E |
| **ENA / NCBI 连通性与实测下载速度** | C |
| 自动给出结论建议（如"下载很慢→建议并行"） | — |

> **只需管理员允许在服务器上运行该脚本**，即可省去大部分问答。
> 脚本只做**只读检查**与一次 30 MB 的下载测速，不安装任何软件、不修改系统配置。

## 五、拿到答案后我会怎么用

| 答案 | 我会做的调整 |
| --- | --- |
| 有 Slurm | 用 `run_all.sh` 已有的 `sbatch` 分支提交，并加依赖串联 |
| 无调度器（含 qsub/bsub） | 用已有的单机分支（`nohup` + `xargs -P`）自行控制并发与容错 |
| 服务器可出网 | 按原方案：服务器下载 + 比对，只回传特征矩阵 |
| **服务器不可出网** | **改方案**：本机下载后上传（本机实测可连通 EBI），或申请网络策略 |
| 存储配额小 | 缩小规模，分批处理，结果即时导出即删除原始数据 |
| 允许容器 | 用 Apptainer 镜像免装环境，最省事 |
| 不允许自建环境 | 改为申请管理员统一安装，或改用容器方案 |
