## 一、先复核上一轮的建议

第十二轮我写下"不建议继续做不依赖数据的东西，请用户在两条路里选"。
本轮目标要求"服务器不可用时先推进不依赖真实数据的部分"，
因此我没有停在建议上，而是**先回头复核我自己的两个长期断言**——
因为一个被反复陈述而未复检的阻塞，本身就可能已经过期。

| 长期断言 | 复核方式 | 结果 |
| --- | --- | --- |
| WSL 不可用、本机无可用 shell | 重跑 `wsl --status`、`wsl -l -v`、逐个查 `bash/sh/dash/busybox` | **成立**：`E_ACCESSDENIED`，且只有 `bash.exe` 而无 `sh`/`dash` |
| 本机无科学计算栈 | `find_spec` 逐包检查 | **成立**：numpy/pandas/matplotlib/streamlit/yaml/pytest/pyarrow **全部缺失**，仅 `sqlite3` 可用 |

两次复核都确认阻塞是真的。但复核过程中发现了一件此前从未注意的事：

**仓库根目录里早已存在 WSL 恢复工具**——`recover_wsl2.ps1` 与 `fix_wsl.cmd`。
读过 `recover_wsl2.ps1`（109 行）后确认，它正是针对我遇到的这个错误：
强制结束 `wslservice`/`vmmemWSL`/`wslhost` 等进程，
重启 `vmcompute`/`hns`/`WslService` 三个服务，再 `wsl --shutdown` 并验证。
脚本自己检查提权状态，未提权则明确退出。

**这把阻塞的性质改变了**：

- 旧表述："WSL 不可用，做不了。"——听起来无解。
- 新表述："**需要一条管理员命令**，而提权必须由你执行。"——可操作。

我**没有**尝试自行提权：`Start-Process -Verb RunAs` 会弹 UAC，
这属于需要用户同意的操作，不该由我单方面发起。

## 二、发现：本项目之前完全没有版本控制

复核目录时发现 `D:\dsh\RiceVar-ID` 下**没有 `.git`**——从第一轮到现在，
全部代码与文档都只存在于工作目录，没有任何历史、没有备份点、
也无法回答"哪个版本产生了哪组数字"。

对一个**以可复现性为卖点**的论文项目，这是真实缺陷，且它正好是
附录 E（代码与数据可获得性）的前提。因此本轮补上 `.gitignore`。

### 2.1 第一版 `.gitignore` 有一个会破坏可复现性的错误

我最初写：

```
data/raw/
data/qc/
```

这在 git 中会**连同 `.gitkeep` 一起忽略**。这些目录里**只有** `.gitkeep`，
于是克隆出来的仓库里 `data/raw/`、`data/qc/`、`reference/`、
`results/*/`、`database/` **根本不存在**，而 `server/` 下的脚本会往里写文件——
直接失败。同样的坑我在 `reference/`、`results/*`、`database/` 上又踩了三遍。

正确写法是 `dir/*` 加显式豁免 `!dir/.gitkeep`。

### 2.2 第二个问题：目录末尾的悬空标题

我把 `## 系统` 这一节的内容删掉后忘了删标题，文件以一个**没有任何规则的章节标题**结尾。
已加测试禁止这种状态。

### 2.3 排除了什么、保留了什么

**排除**（体积大或可重新下载）：原始 FASTQ/SRA、BAM/CRAM/SAM、
参考基因组及索引、中间产物、数据库文件、以及
`data/metadata/candidates/xml_cache/`（**约 110 MB** 的 NCBI 原始 XML 响应）。

**保留**（论文数字的直接依据）：两个面板清单、预检清单、
`ena_search_summary.tsv`、`candidate_samples.tsv`、`sample_attrs.tsv`、
`variety_canonical.tsv`、`duplicate_samples.tsv`、全部论文与附录。

**关键约束**：`data/metadata/` 下**除 `xml_cache` 外任何文件都不得被忽略**——
这些文件是论文里每一个数字的证据，代码离开了它们就无法支撑自己的结论。

该约束由 `tests/test_gitignore.py` 的 10 项测试锁定，双向断言：
该忽略的必须忽略、论文依赖的必须保留、**且每条保留规则所指路径必须真实存在**
（指向不存在文件的保护规则是死规则，不是保护）。

## 四、验证方式：让附录自己接受检查

附录 E 声称描述了这个仓库。因此写 `tests/test_appendix_availability.py`（14 项），
把它的每一条结构性断言变成可执行检查：

- 附录中点名的**每一个仓库路径必须真实存在**；
- ASCII 目录树里列的**每一个阶段脚本必须存在**，且**不得遗漏任何实际存在的阶段脚本**；
- 声明的运行命令（`00_probe.sh`、`01_setup_env.sh`、`run_all.sh`）必须真实存在；
- **334.71 GiB 由测试重新从两个清单复算**（按 `;` 拆分后求和，与附录一致）；
- `.git` **必须不存在**（与附录"尚未纳入版本控制"一致）；
- 附录中不得出现任何结果指标数字。

**过程中抓到一处真实遗漏**：附录 E 只提了 `environment.yml`，漏了 `requirements.txt`
（pip 侧的依赖记录）。只给其中一份无法重建完整环境。已补。

**只有拿到动作 2 的结果，才可能有真实实验数据**；
