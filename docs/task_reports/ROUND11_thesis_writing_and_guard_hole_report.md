## 五、发现的真实缺陷：占位符守卫存在漏报

写作过程中触发了 `verify_thesis_placeholders.py` 两次，**两次都是真问题**。

### 缺陷 1：守卫只有两类，无法表达"整理事实"

原守卫只认"允许的设计常量"与"可疑结果数值"。
而 2.1 节的检索数字既非设计常量、也非本文测得的结果。
若强行塞进白名单，就等于把守卫削弱；若改成占位符，反而降低论文信息量。

**修法（加第三类并强制溯源）**：新增 `CURATION_SOURCE`——
只有当同段内引用 `data/metadata/...` 或 `docs/...` 时才放行整理数字；
同时新增 `RESULT_METRICS`——**若同一行还出现本文自己测得的指标
（准确率/recall/实测深度/Q30/比对率…），一律判失败**。

即"引用来源**不能**为编造的结果指标背书"。

### 缺陷 2（**既有漏洞，非本轮引入**）：任何 ≤1 的倍数都被放行

原规则为放行设计梯度 `0.02×–1×`，写成"数值 ≤1.0 且单位是 ×/倍 就跳过"。
但**实测深度通常也小于 1×**，于是

> 实测深度为 0.98×

被静默放过——正是守卫本该抓住的那类数字。

这个漏洞**不是本轮改坏的**，而是本来就在；是编写"新改动不得破坏既有功能"
的反向用例 `test_measured_depth_still_fails` 时暴露的。
**修法**：要求行内出现**设计措辞**（梯度 / 候选深度 / 降采样至 / 降至 /
预设 / 目标深度），且不得出现结果指标词。
并有意保留保守侧：含义不清的裸倍数（"覆盖度为 0.3×"）仍按结果处理。

### 边界验证（7 个用例全部符合预期）

| 输入 | 期望 | 实际 |
| --- | --- | --- |
| 编造准确率，无来源 | 失败 | ✅ 失败 |
| 编造准确率，**近旁有来源** | 失败 | ✅ 失败 |
| 编造 recall，近旁有来源 | 失败 | ✅ 失败 |
| 无来源的未知百分比 | 失败 | ✅ 失败 |
| 真实整理数字 + 来源 | 通过 | ✅ 通过 |
| 整理数字 + **来源在下一行** | 通过 | ✅ 通过 |
| 设计梯度常量 | 通过 | ✅ 通过 |

已固化为 `tests/test_thesis_placeholder_guard.py`（9 项）。
另据此把守卫从**逐行**改为**逐段**检查：Markdown 里引文常因换行
落在数字的下一行，逐行检查会逼作者把路径塞在数字旁边，
反而催生"为过检而撒路径"的坏习惯。

三处正文因此被守卫拦下并修正：
第 47 行的无出处倍数（已改为定性 + 占位引文）、
第 138 行的填充率（补溯源）、第 320 行的"约 75%"（改为引用 2.1.2 节）。
