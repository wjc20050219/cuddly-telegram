## 2. 附录 C：把打分公式从代码里"挖"出来

此前的论文章节提到位点筛选，但只给参数、不给公式，读者无法据此复现。

本轮读取 `scripts/select_snp_markers.py` 全部 272 行，把**实际实现**整理为可复现的规格：

- **三个位点指标**：判型率、MAF、**区分度**（1 − 随机两样本基因型相同的概率）。
  明确写出区分度公式，并说明**本项目选它而非 MAF 作为主排序键**是设计选择，
  **不是领域标准做法**——避免让读者误以为这是通行惯例。
- **七步硬性过滤**（格式 → 二等位 SNP → FILTER → QUAL → 逐样本 DP/GQ →
  缺失率 → MAF），并说明每步的计数键，便于对照运行日志排查。
- **区分"阈值"与"排序"**：阈值决定谁能参选，排序决定谁胜出。这两者混淆是常见误解。
- **五键字典序排序**：区分度 → 判型率 → MAF → QUAL → **出现次序取负**。
  末项取负的作用是保证**全序**，从而结果可复现——代码注释里正是这么写的。
- **候选池 = 50 × 最大档位 = 100,000**，用最小堆流式筛选，内存不随变异数增长。
- **贪心间距过滤**：同染色体任意两位点 ≥1000 bp；并说明为何选贪心而非全局最优。
- **嵌套档位的子集性质**：500 ⊂ 1000 ⊂ 2000，使"档位增加带来的变化"成为受控比较。
- **防泄漏约束**：`--panel-role` 的 `choices` 只有 `pilot` 一个取值，
  即**从代码层面禁止**用独立面板选 marker，而非依赖使用者自觉。

## 3. 附录 C 的验证：不比对参数，而是重算公式

关键判断：**只断言"文档里的默认参数与脚本一致"几乎没有验证价值**——

- 无已判型样本 → 三指标均为 0

## 6. 本轮唯一的真实代码缺陷：豁免机制未 fail-closed

附录 D 的 D.5 节职责是说明守卫如何区分"可写事实"与"臆造结果"，
因此**必须引用被禁止的数值作为反例**，导致守卫正确地把附录 D 判为违规。

为此新增"元文档豁免"：文件在头部声明 `<!-- meta-document: marker-guard -->`，
并把反例包在 `guard-examples-start` / `guard-examples-end` 之间。

**第一版实现有真实缺陷**：使用非贪婪正则 `start(.*?)end` 配合 `re.S`。
看似安全，实则**在缺少结束标记时 `(.*?)` 会一路匹配到文件末尾**——
一个忘记写的结束标签就会让守卫在其后**完全失效**。

发现方式值得一提：我**先写滥用测试再信任豁免**，其中一条测试写下了
"未闭合区块豁免到 EOF"这一预期，它**通过**了——正因为通过，才看出这是缺陷而非特性。

修复：改为显式扫描配对结束标记；**未闭合的区块一律不豁免**（fail-closed）。

同时用 7 项测试锁定豁免不可被滥用：
仅声明不豁免、仅标记不豁免、区块内的反例豁免、**区块结束后立即恢复检查**、
未闭合区块不豁免、真实附录 D 必须通过。
