### 2.1 ★ 第 3 类为什么必须保留

"同一品种有多个 run"看起来像重复，但**恰恰是本项目 Q5（指纹稳定性）所需的核心材料**。
若当作重复删掉，就**亲手毁掉了唯一能验证"同品种跨测序批次指纹是否稳定"的数据**。

> 这正是任务书第四十三节"审稿人模式"要警惕的问题：
> **把有价值的生物学重复误当成技术噪声删掉。**

## 三、★ 最重要的发现：单一品种占 36%，且来自 EMS 突变体库

| 规范品种 | run 数 | 占可用样本 |
| --- | ---: | ---: |
| **Zhonghua 11** | **5,360** | ★ **36.1%** |
| Kitaake | 62 | 0.4% |
| Nipponbare | 53 | 0.4% |

**这 5,360 条里有 5,344 条来自同一个 BioProject：`PRJDB38331`。**

而该 BioProject 的 `study_title` 是：

```
rice ZH11 ems4611 database (PRJCA020505)
```

### ⚠️ 这意味着什么

**这是 EMS 突变体库**。其中的样本是**经 EMS 诱变产生的突变体株系**
（样本标题形如 `B1674 (CRX842160)`），**遗传上与野生型中花 11 不同**。

**若把它们当作"中花 11 的 5,360 次重复"，会是严重的数据错误**：
1. 面板会被单一品种主导（36%）；
2. 更严重的是——**它们根本不是同一个基因型**，标签本身就是错的。

### 处理

- 在 TASK-014 中通过 `study_title` + 样本标题模式**识别并排除**（共剔除 5,437 条）；
- 识别必须结合 `study_title`——只看样本标题会漏判（标题只有株系编号）。

> **这也是为什么我专门回头补抓了 `study_title` 字段。**
> 首轮只用样本标题过滤时只抓到 3,981 条，补上 `study_title` 后抓到 5,437 条。
