# 第二十一轮报告：任务清单的自述与表格自相矛盾

**日期**：2026-09-21
**范围**：规范 C `TASK-001~048`
**触发**：用户提问"已经完成多少了？"

## 1 本轮起点

用户问"已经完成多少了"。我没有凭记忆回答，而是写了一个脚本去数
`UNDERGRADUATE_TASK_LIST.md` 里每一行的状态标记。结果是：

| 状态 | 数量 |
| --- | --- |
| ✅ 完成 | 8 |
| 🔶 代码完成、无真实数据 | 36 |
| ⬜ 未开始 | 4 |

对照之下，同一份文件的「状态口径」一节末尾写着：

> 当前项目**没有任何 ✅**。

**这就是本轮发现的缺陷**：正文说一项 ✅ 都没有，表格里有 8 项。

## 2 这项缺陷的性质与前面几项不同

前面几轮的缺陷方向是"**该记的没记**"（漏记缺陷、漏引用图、漏测试用例）。
这一项相反：**文件对自己状态的自述与自身内容不符**。

读者（包括答辩评委）会据此**低估**已完成的工作，或者反过来
开始怀疑整份清单是否可靠。两种后果都不好。

### 2.1 那句话曾经是真的

这是最值得记录的地方：在 TASK-002~009 完成之前，项目**确实**一项 ✅ 也没有，
那句话当时是正确的。它变成假话，不是因为有人写错了，
而是因为**别人默默完成了工作，而这句话没有被同步更新**。

### 2.2 根因在口径定义本身

原来的口径是：

- ✅ 完成：有可追溯到结果文件的真实数值。

而实际标 ✅ 的 8 项是：项目目录、软件环境、参考论文、数据检索、
样本筛选、品种名称整理、Pilot 数据集、独立测试集——
全部位于"环境、文献和数据"一节，属于**整理类**任务。

它们的产出（`PROJECT_STRUCTURE.md`、`candidate_samples.tsv`、
`variety_alias.tsv`、两个面板清单等）**确实可追溯**，
但**不含实验测量值**。定义容不下这类任务，
于是"没有任何 ✅"这个结论就从定义里被推了出来，
而它和表格逐行统计的结果矛盾。

**这不是数字写错，是定义不完整。**

## 3 修复

1. ✅ 细分为两类，并在口径里明确区分：
   - **整理类**：产出是可追溯的仓库文件，**不含实验测量值**；
   - **实验类**：产出是**可追溯到结果文件的真实数值**。

2. 正文改为准确陈述：列出"**8 项 ✅，全部属于整理类**"及具体任务号，
   并保留实质结论"**当前项目没有任何 ✅ 级实验任务**"。

3. 新增 `tests/test_task_list_status_counts.py`（7 项）：
   - 表格覆盖全部 48 项，每行**恰好一个**状态标记；
   - 正文声明的 ✅ 数量 == 表格实际数量；
   - 正文列举的 ✅ 任务号 == 表格标 ✅ 的任务号；
   - **保护论文诚信的那一条**：38 项需要真实数据的实验类任务
     **一律不得标 ✅**；
   - 口径必须保留"整理类/实验类"的区分；
   - 旧假命题不得再出现。

守卫的写法是关键：**不检查某个固定的数字**（那会立刻过期），
而是要求**正文与表格互相一致**。这样无论将来完成多少项，
数字变化不会导致守卫失败，只有"说法与事实不符"才会失败。

## 5 我自己在本轮的错误

1. **正则写错**：第一版要求"**8 项 ✅**"的 ✅ 后紧跟 `**`，
   但正文里 ✅ 后面还有说明文字，于是匹配不到、测试报错。
   这是我第二次犯"断言比事实更严格"的错。
2. **忘了更新耦合数字**：加完测试文件后，全套件报 3 项失败
   （D.8 的测试总数、测试文件数、以及 VCS 未跟踪文件守卫）。
   三处**都是守卫在正确报警**，不是回归。动态计数守卫
   在本轮又一次完成了它的职责。

## 7 教训

**一句正确的话会因事实变化而变成错误的话，必须随事实更新。**

本项目此前反复强调"测试断言过的数字会随事实变化而过期"，
并为此设了动态计数守卫（见附录 D.8）。但那只覆盖了**数字**，
没有覆盖**自然语言里的全称断言**。

"没有任何 X"这一形式尤其危险：它最好写、最让人放心、
也最容易在别人默默完成工作之后变成假的。
**凡是在文档里写"全部""从未""没有任何"这类全称断言，
都应当考虑给它配一条能随事实失败的检查，或者干脆改成可核对的具体清单。**
