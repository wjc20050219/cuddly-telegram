## 二、★ 三条核心发现

### 2.1 没有"超低深度 WGS 做品种鉴定"的直接先例

检索到的低深度研究，应用目标**全部是**群体基因组学、GWAS、基因组选择、
肿瘤 CNV 检测、产前诊断——**没有一个是品种身份识别**。

> **这是本项目新颖性的来源，也是审稿人会更严格质疑的地方。**
> 表述须用"据我们所知（to our knowledge）"，且投稿前须用更全面的检索复核。

### 2.2 ★★ 低深度文献依赖**填补**，与本项目范式不同（最容易被误用）

| | 填补范式 | **直接检测范式（本项目）** |
| --- | --- | --- |
| 原理 | 用参考面板统计推断基因型 | 直接观测标记存在/缺失 |
| 需要参考面板 | ★ 必须有 | 不需要 |
| 代表 | STITCH / GLIMPSE / Beagle | **Niu et al. 2024（小麦论文）** |

**因此以下结论不能直接引用支持本项目**：

- "ulcWGS 0.4× 可捕获 99.9% 常见变异"（Front Genet 2021）——**依赖填补**
- "skim-seq 0.01×–0.05× 可用于基因组选择"（Plant Genome 2025）——**依赖 STITCH 填补**，
  且物种是异交多倍体长雄麦草，与自交二倍体水稻差异大

> **必须写进论文**：本项目的指纹是**直接观测**得到的，不经过填补；
> 现有低深度文献的阳性结论大部分建立在填补之上，**不能作为本项目可行性的直接证据**。

### 2.3 ★★ 一条必须重视的**负面**证据

**PMID 38216889**（Genet Sel Evol 2024，"A cautionary tale of low-pass sequencing"）：

- 3.8× 及以上时关联结果与 43.5× 高度相关（r ≥ 0.97）
- **0.9× 时降至 r ≤ 0.8**
- ★ "**当个体携带参考面板中不存在的等位基因时，会产生错误的等位基因指派**"
- ★ "**若需要准确分型，我们主张使用高深度（>20×）**"

**对本项目的三条含义**：
1. 0.9× 已现明显精度下降，而本项目要测到 **0.01×**——**必须用实测数据回答，不能外推**；
2. **开放集问题**：库中没有的品种会被错误指派。这正是品种鉴定系统的核心风险，
   也是小麦论文设 85% 阈值的用意。**本项目必须为水稻重算阈值，并显式报告"拒识"能力**；
3. 该文主张 >20×——与我们选 Panel 时定的 20–50× 相符（**用于建真值，不是用于识别**）。

## 四、publication 字段回填（含可信度分级）

### 4.1 为什么难

| 尝试路径 | 结果 |
| --- | --- |
| ENA `result=study` 的文献字段 | ❌ **不存在**（29 个字段里只有 `first_public`） |

### 4.2 ★ 用"run 数 vs 论文自述样本量"做可信度判别

人工核验 3 例后发现规模一致性是有效信号，于是把它自动化：

| 项目 | 本表 run 数 | 论文自述样本量 | 比值 | 判定 |
| --- | ---: | ---: | ---: | --- |
| PRJNA844290 | 547 | 546 | **1.00** | ★ 高度可信 |
| PRJNA743713 | 119 | 123 | **0.97** | ★ 高度可信 |
| PRJNA1003283 | 324 | 284 | 1.14 | ★ 高度可信 |
| PRJNA656900 | 1,137 | 517 | 2.20 | 合理 |

**判定分级**（写入主表 `publication` 列的前缀）：

| 前缀 | 含义 | run 数（主表） |
| --- | --- | ---: |
| `[MATCH]` | run/样本 ≈ 1:1，**高度可信** | **1,593** |
| `[PLAUSIBLE]` | 每样本多次测序，合理 | 1,245 |
| `[PARTIAL]` | 本表 run 少于论文自述，可能只是一部分数据 | 626 |
| `[WEAK]` | ★ 差距过大，**疑为误匹配** | 461 |
| `[?]` | 摘要未给样本量，无法核验 | 7,115 |

## 五、⚠️ 本任务中我犯的两个错误（均已更正）

### 5.1 DOI 抓错：抓到了**被引文献**的 DOI

`fetch_abstracts.py` 初版用 XPath `.//ArticleId` 提取 DOI，
该表达式会**搜到参考文献列表里的 ArticleId**。

- **症状**：PMID 30992303（*Genome Research*）的 DOI 被标为 `10.1007/s00122-013-2177-7`
  ——那是 *TAG* 的 DOI，与期刊不符。
- **发现方式**：怀疑后与 esummary 路径的结果**交叉比对**，发现两者不一致。
- **修正**：限定 XPath 为 `PubmedData/ArticleIdList`，并加 `ELocationID` 兜底。
  修正后 10 篇 DOI 全部与期刊对应。
- **教训**：**两条独立路径交叉验证**是发现此类错误的有效手段。

### 5.2 人工核验时抄错了 run 数

在 `verify_pub_match.py` 里我把 `PRJNA743713` 的 run 数写成 **1,137**
（那是 `PRJNA656900` 的数字），据此判断该匹配"存疑"。

- **实际**：PRJNA743713 是 **119 run ↔ 论文 123 varieties = 0.97×**，
  **是高度可信的匹配**。
- **后果**：我一度把它当成"全文匹配不可靠"的例证，**结论方向错了**。
- **修正**：在自动化分级中被纠正（脚本读的是真实字段，不是我手抄的数字）。
- **教训**：**凡是能由脚本算的数字，不要手抄进判断**。
