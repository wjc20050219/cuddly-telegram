## 三、问题与决策记录

1. 系统自带 Python 3.7.3 过旧 → 项目统一使用 WSL2 内 conda 环境 `ricevar`。
2. 生信工具链无 Windows 原生版本 → 采用 WSL2 + Ubuntu 方案（2026-09-15 完成部署）。
3. **Miniforge → Miniconda 替换**：`wsl --update --web-download` 正常，但 WSL 内 `github.com` 与 TUNA `github-release/LatestRelease` 两条 Miniforge 下载源均失败（exit 20）。改用 TUNA Anaconda 镜像的 Miniconda3（`mirrors.tuna.tsinghua.edu.cn/anaconda/miniconda/Miniconda3-latest-Linux-x86_64.sh`），一次性成功。
4. **environment.yml v2 修订（可解性）**：首版在 `channel_priority: flexible` 下求解 41 分钟仍未收敛（CPU 99%、RSS 7 GB，属求解爆炸）。修订三点后 **数秒内求解成功**：
   - `python=3.10` → `python=3.11`（snakemake 9 要求 ≥3.11，原组合与 `snakemake-executor-plugin-cluster-generic` 冲突）；
   - 移除 `r-tidyverse`（拉入数百个 R 包，是求解爆炸主因；R 绘图包按需在 Phase 6 前单独安装）；
   - 移除 `mamba`（conda ≥24 已内置 libmamba），并将 `channel_priority` 设为 **strict**。
5. **jellyfish 包名坑**：`jellyfish`（conda-forge）是 Python 绑定库，**不含** k-mer 计数 CLI；CLI 需 `kmer-jellyfish`（bioconda）。已补装。
   ⚠️ **2026-09-16 补充修复**：当时只把 CLI 补装进当前环境，**忘了同步修改 `environment.yml`**——
   yml 中仍只声明 `jellyfish`，意味着**照 yml 重建环境会装到 Python 绑定、拿不到 `jellyfish` 可执行文件**。
   现已改为同时声明 `kmer-jellyfish`（CLI）与 `jellyfish`（Python 绑定）并加注释说明区别。
   **复现性缺陷已消除。**
6. **hmmlearn 缺失（2026-09-16 补装）**：论文 CNVb 方法需用 HMM 平滑窗口深度
   （`n_components=3, n_iter=60, tol=0.001`，见 TASK-004 解析第 4 节 Step 1），
   但首版 `environment.yml` 与 `requirements.txt` **均未包含**该依赖。
   已安装 **hmmlearn 0.3.3** 并补入两个依赖文件（安装时 numpy/scipy/scikit-learn 均
   "already satisfied"，未扰动既有环境）。
7. `scripts/record_versions.sh` 因 `set -euo pipefail` + 工具非零退出码（bwa-mem2 `--version`）而中断 → 已改用 `scripts/collect_env_versions.sh`（本文件第五节即其输出）。
